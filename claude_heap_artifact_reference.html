01 — หลักการ

Priority Queue (Heap) คืออะไร และทำไมต้องใช้ Tree

ไล่อ่านตั้งแต่ concept ไปจนถึงโค้ดจริง 6 หัวข้อ

1Priority Queue คือ ADT ที่ "ดึงตัวสำคัญสุดออกก่อนเสมอ"

Priority Queue ไม่ใช่ FIFO queue ธรรมดา แต่เป็นโครงสร้างข้อมูลที่รองรับอย่างน้อย 2 operation: insert (เหมือน enqueue) และ deleteMin (ค้นหา คืนค่า และลบสมาชิกที่ค่าน้อยที่สุดออก — เหมือน dequeue แต่ดึง "ตัวเล็กสุด" แทนที่จะดึง "ตัวแรกสุด")

ใช้งานจริงใน: คิวเครื่องพิมพ์ (งานสำคัญพิมพ์ก่อน), การจัดคิว process ของ OS, และ graph algorithm หลายตัว (เช่น Dijkstra's shortest path)

2ทำไมไม่ใช้ list ธรรมดา — ต้องมี Binary Heap

ถ้า implement ตรงไปตรงมาด้วย list จะเจอปัญหา insert เร็วแล้ว deleteMin ช้า หรือกลับกันเสมอ Binary Heap คือ compromise ที่ทำให้ทั้งสอง operation เร็วพร้อมกัน:

List เรียงลำดับอยู่แล้วO(N) — ต้องเลื่อนหาตำแหน่งแทรกO(1)

Binary Heap เป็นแค่หนึ่งในหลายวิธี (ยังมี d-Heap, Leftist Heap, Binomial Heap, Fibonacci Heap) แต่เป็นแบบที่ใช้บ่อยที่สุด เพราะ implement ง่ายและมี constant factor ต่ำ

3คุณสมบัติที่ 1 — Structure Property

Binary Heap ต้องเป็น complete binary tree: เติมเต็มทุกชั้นจากซ้ายไปขวา ห้ามมีช่องว่างระหว่างทาง คุณสมบัตินี้ทำให้ tree มีรูปแบบตายตัว จึงแทนด้วย array ได้พอดีโดยไม่ต้องเก็บ pointer ซ้าย/ขวา/พ่อเลย

การแปลง index ↔ ตำแหน่งใน tree

สำหรับสมาชิกที่ตำแหน่ง i ใน array (เริ่มนับที่ index 1 เพราะ index 0 ไม่ใช้งาน)

left child = 2i right child = 2i+1 parent = i // 2

ทำไมความสูงเป็น O(log N)

ถ้า heap สูง h ชั้น จะมีสมาชิกได้ระหว่าง 2ʰ ถึง 2ʰ⁺¹−1 ตัว เพราะ tree เติมเต็มแน่นทุกชั้น ดังนั้นความสูงของ heap ที่มี N ตัวจึงเป็น O(log N) — นี่คือเหตุผลที่ insert/deleteMin เร็ว เพราะแค่เดินขึ้น-ลงตามความสูงของ tree เท่านั้น

4คุณสมบัติที่ 2 — Heap-Order Property

ค่าของพ่อ ≤ ค่าของลูกเสมอ (สำหรับ min-heap) ทุกโหนดยกเว้น root ผลที่ตามมาคือ ค่าน้อยที่สุดของทั้งต้นไม้อยู่ที่ root เสมอ (array[1]) — deleteMin จึงรู้ตำแหน่งคำตอบทันที โดยไม่ต้องค้นหาเลย

5Insert — ใส่ค่าใหม่โดยไม่ทำลาย heap property

หลักการคือสร้าง "ช่องว่าง (hole)" ที่ตำแหน่งถัดไปสุดท้ายของ array (รักษา structure property) แล้วเทียบค่าใหม่กับพ่อของ hole ไปเรื่อยๆ ถ้าค่าใหม่ น้อยกว่า พ่อ แสดงว่าผิด heap-order → ย้ายพ่อลงมาแทนที่ hole แล้วขยับ hole ขึ้นไปแทนตำแหน่งพ่อ (เรียกว่า percolate up) ทำซ้ำจนกว่าค่าใหม่จะไม่เล็กกว่าพ่อ แล้วค่อยใส่ค่าจริงลงใน hole

  • สร้าง hole ที่ตำแหน่ง currentSize หลังเพิ่มขนาด
  • วนเทียบ x < array[hole // 2] — ถ้าจริง ย้ายพ่อลงมา แล้ว hole //= 2
  • ออกจากลูปเมื่อ hole ถึง root หรือค่าใหม่ไม่เล็กกว่าพ่อแล้ว
  • ใส่ค่าจริงที่ hole สุดท้าย

6deleteMin — ดึงตัวน้อยสุดออกโดยไม่ทำลาย heap property

เก็บค่า root ไว้เป็นคำตอบ แล้วเอา element ตัวสุดท้ายของ array มาใส่ที่ root แทน (รักษา structure property) ค่าที่ย้ายมาอาจใหญ่เกินไปจนผิด heap-order → เทียบกับ ลูกที่มีค่าน้อยกว่า ระหว่างลูกซ้ายกับลูกขวา ถ้า root ใหญ่กว่า ให้สลับค่าลงไป (เรียกว่า percolate down) ทำซ้ำจนกว่าจะไม่ผิด heap-order หรือไม่มีลูกแล้ว

เลื่อนลงไปด้านล่างเพื่อดู insert/deleteMin ทำงานจริงแบบ debugger ทีละบรรทัด 👇

02 — build from empty
