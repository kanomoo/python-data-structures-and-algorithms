Binary Heap ตั้งแต่ต้นจนจบ

อธิบายหลักการ Priority Queue / Binary Heap ทีละขั้น พร้อมไล่โค้ด insert() และ deleteMin() แบบ Step-by-Step Interactive Debugger จริง — รวมทั้งตัวอย่างสร้าง heap จากชุดข้อสอบ [13, 21, 16, 24, 31, 19, 68, 65, 26, 32]

01 — หลักการ

Priority Queue (Heap) คืออะไร และทำไมต้องใช้ Tree

ไล่อ่านตั้งแต่ concept ไปจนถึงโครงสร้างข้อมูลจริง 6 หัวข้อสำคัญที่ออกสอบบ่อยที่สุด

1Priority Queue คือ ADT ที่ "ดึงตัวสำคัญสุดออกก่อนเสมอ"

Priority Queue ไม่ใช่ FIFO Queue ธรรมดา แต่เป็นโครงสร้างข้อมูลที่รองรับอย่างน้อย 2 operation สำคัญ: insert (เหมือน enqueue) และ deleteMin (ค้นหา คืนค่า และลบสมาชิกที่ค่าน้อยที่สุดออก — เหมือน dequeue แต่ดึง "ตัวเล็กสุด" แทนที่จะดึง "ตัวแรกสุด")

ใช้งานจริงใน: คิวเครื่องพิมพ์ (งานสำคัญพิมพ์ก่อน), การจัดคิว process ของ OS Scheduler, และ Graph Algorithm หัวใจสำคัญอย่าง Dijkstra's Shortest Path และ Prim's MST

2ทำไมไม่ใช้ list ธรรมดา — ทำไมต้องมี Binary Heap

ถ้า implement ตรงไปตรงมาด้วย List ธรรมดา จะเจอปัญหา Trade-off ร้ายแรง: ถ้า insert เร็ว deleteMin จะช้ามาก หรือถ้า deleteMin เร็ว insert จะช้ามาก Binary Heap คือ Compromise ที่ทำให้ทั้งสอง operation เร็วระดับ logarithmic time พร้อมกัน:

3คุณสมบัติที่ 1 — Structure Property (Complete Binary Tree)

Binary Heap ต้องเป็น Complete Binary Tree: เติมเต็มแน่นทุกชั้นจากซ้ายไปขวา ห้ามมีช่องว่างระหว่างทาง คุณสมบัตินี้ทำให้ tree มีรูปแบบคงที่ตายตัว จึงแทนด้วย Array 1-Based Indexing ได้สมบูรณ์แบบโดยไม่ต้องเก็บ Pointer ซ้าย/ขวา/พ่อ ให้เปลืองหน่วยความจำเลย

สูตรคำนวณ Index ↔ ตำแหน่งใน Tree

สำหรับสมาชิกที่ตำแหน่ง i ใน array (เริ่มนับที่ index 1 เพราะ index 0 เว้นว่างไว้เป็น Sentinel):

Left Child = 2i Right Child = 2i + 1 Parent = i // 2

ทำไมความสูงจึงเป็น O(log N)

ถ้า Heap สูง h ชั้น จะมีสมาชิกได้แน่นขนัดระหว่าง 2ʰ ถึง 2ʰ⁺¹−1 ตัว ดังนั้นความสูงของ Heap ที่มี N ตัวจึงการันตีเป็น O(log N) เสมอ — นี่คือเหตุผลที่ insert และ deleteMin ทำงานได้รวดเร็วอย่างยิ่ง

4คุณสมบัติที่ 2 — Heap-Order Property (Min-Heap vs Max-Heap)

ค่าของพ่อ ≤ ค่าของลูกเสมอ (สำหรับ Min-Heap) ในทุกโหนดยกเว้น root ผลที่ตามมาคือ ค่าน้อยที่สุดของทั้งต้นไม้อยู่ที่ Root เสมอ (array[1]) — การค้นหาค่าต่ำสุดจึงทำได้ในเวลา O(1) ทันทีโดยไม่ต้องค้นหา!

5Insert Operation — Percolate Up

หลักการคือสร้าง "ช่องว่าง (Hole)" ที่ตำแหน่งถัดไปสุดท้ายของ Array เพื่อรักษา Structure Property ก่อน แล้ววนลูปเปรียบเทียบค่าใหม่กับพ่อของ Hole ถ้าค่าใหม่ น้อยกว่าพ่อ แสดงว่าผิด Heap-Order → ดึงพ่อลงมาแทนที่ แล้วเลื่อน Hole ขึ้นไปแทนตำแหน่งพ่อ (Percolate Up) ทำซ้ำจนกว่าจะไม่ผิดเงื่อนไข แล้วค่อยใส่ค่าจริงลงไป

6deleteMin Operation — Percolate Down

เก็บค่าที่ Root (array[1]) ไว้เป็นผลลัพธ์ แล้วนำค่าที่ตำแหน่งสุดท้ายของ Heap มาวางไว้ที่ Root ชั่วคราว (พร้อมลดขนาด currentSize -= 1) จากนั้นเลื่อนค่าลงไปเปรียบเทียบกับ ลูกที่มีค่าน้อยกว่า ระหว่างลูกซ้ายและลูกขวา ถ้าค่าใหญ่กว่าลูก ให้สลับค่าลูกขึ้นมา แล้วขยับ Hole ลงไป (Percolate Down) จนกระทั่งได้ตำแหน่งที่ถูกต้องสมบูรณ์

Binary Search Tree (BST) ตั้งแต่ต้นจนจบ

ทำความเข้าใจ BST Property อย่างลึกซึ้ง พร้อมการจำลอง insert(), search(), และ delete() ครบทั้ง 3 กรณีสำคัญ (Leaf, One Child, Two Children พร้อม In-order Successor)

01 — หลักการ

BST Invariant & โครงสร้างข้อมูลแบบต้นไม้ค้นหา

คุณสมบัติที่ทำให้ BST สามารถค้นหา แทรก และลบข้อมูลได้รวดเร็วเฉลี่ย O(log N)

1กฎเหล็กของ BST Invariant

ในทุกโหนด root ของ BST: ทุกค่าใน Subtree ซ้าย ต้องน้อยกว่า Root (Left < Root) และทุกค่าใน Subtree ขวา ต้องมากกว่า Root (Root < Right) ผลลัพธ์ทำให้การท่องแบบ In-Order Traversal (Left → Root → Right) จะได้ข้อมูลเรียงลำดับจากน้อยไปมากเสมอ!

2การลบโหนด (Deletion) ครบทั้ง 3 กรณี

กรณีที่ 1: โหนดใบ (Leaf Node)

โหนดที่ต้องการลบไม่มีลูกเลย → ปลดตัวชี้จากโหนดพ่อเป็น None ได้ทันที ทำงานในเวลา O(h)

กรณีที่ 2: มีลูกเพียง 1 ข้าง

ยกโหนดลูกเพียงข้างเดียวนั้นขึ้นมาแทนที่ตำแหน่งโหนดที่ถูกลบได้โดยตรง

กรณีที่ 3: มีลูกทั้ง 2 ข้าง (ออกสอบบ่อยที่สุด!)

ค้นหา In-Order Successor (ค่าน้อยที่สุดใน Subtree ขวา) หรือ In-Order Predecessor (ค่ามากที่สุดใน Subtree ซ้าย) นำค่านั้นมาเขียนทับที่โหนดเดิม จากนั้นเรียกคำสั่ง Delete แบบ Recursive เพื่อลบโหนด Successor นั้นทิ้ง ซึ่งจะแปลงเป็นกรณีที่ 1 หรือ 2 เสมอ

Hash Table & Collision Resolution

เข้าใจฟังก์ชันแฮช h(k) = k mod M, อัตราส่วนความหนาแน่น Load Factor λ = N / M และการแก้ปัญหาการชนกันของข้อมูลด้วยทั้ง Separate Chaining และ Open Addressing (Linear Probing)

01 — หลักการ

ทำไมต้องแฮช และจัดการการชนอย่างไร

เปรียบเทียบกลยุทธ์การแก้ปัญหาการชน (Collision Resolution Strategies)

1Hash Function & Load Factor (λ)

ฟังก์ชันแฮชแปลงคีย์ใดๆ ให้เป็นดัชนี Array ระหว่าง 0 .. M - 1 โดย λ = N / M บอกถึงความหนาแน่นของตาราง เมื่อข้อมูลสองค่าแฮชได้ช่องเดียวกันจะเกิด Collision (การชน)

Separate Chaining

แต่ละช่องในตารางเก็บหัวพอยน์เตอร์ของ Linked List ถ้าข้อมูลชนกันจะนำไปต่อท้ายหรือใส่หัวแถว ข้อดีคือค่าความหนาแน่น λ (Load Factor) เกิน 1 ได้

Open Addressing (Linear Probing)

เก็บข้อมูลในตัวตารางโดยตรง ถ้าเกิดชนกันจะขยับหาช่องว่างถัดไปทีละ 1 ช่อง: h(k, i) = (h(k) + i) mod M ข้อควรระวังคือเกิด Primary Clustering

01 — นิยามและหลักการทางทฤษฎี

Topological Sort บน Directed Acyclic Graph (DAG)

ทำความเข้าใจเงื่อนไขการเรียงลำดับงานตามความสัมพันธ์แบบมีทิศทาง และแนวคิดของ Indegree

🎯 นิยาม Topological Order

คือการจัดเรียงจุดยอดในกราฟแบบเส้นตรง โดยมีเงื่อนไขว่า สำหรับทุกเส้นเชื่อมระบุทิศทาง (u, v) จุดยอด u จะต้องปรากฏขึ้นก่อน v ในลำดับเสมอ ใช้ในการจัดตารางเรียนที่ต้องเรียนวิชาบังคับก่อน (Prerequisite Courses) หรือการคอมไพล์ซอฟต์แวร์

🔄 เงื่อนไข DAG & วงรอบ (Cycle)

Topological Sort จะเกิดขึ้นได้ก็ต่อเมื่อกราฟเป็น DAG (Directed Acyclic Graph) เท่านั้น หากกราฟมี Cycle แม้แต่วงเดียว จะไม่มีทางจัดลำดับได้เลย เพราะจะเกิดการวนรอซึ่งกันและกัน (Deadlock)

📥 คอนเซปต์ Indegree = 0

Indegree คือจำนวนเส้นเชื่อมที่ชี้พุ่งเข้ามายังจุดยอดนั้น จุดยอดที่มี Indegree = 0 หมายถึง "ไม่มีงานหรือเงื่อนไขค้างอยู่แล้ว สามารถลงมือทำได้ทันที" จึงพร้อมนำเข้าคิวรอประมวลผล

02 — การแทนกราฟและความสิ้นเปลืองหน่วยความจำ

Adjacency Matrix ขนาด 7 × 7 & การคำนวณ Memory Waste

ข้อสอบถามคำนวณเปอร์เซ็นต์พื้นที่สิ้นเปลืองของตารางแบบ Matrix เมื่อเทียบกับกราฟ 7 จุดยอด 12 เส้นเชื่อม

2การคำนวณสูตรสัดส่วนความสูญเสีย (Memory Waste)

ตารางมีขนาดทั้งหมด 7 × 7 = 49 ช่อง โดยมีเส้นเชื่อมจริงเพียง 12 เส้น:

ช่องที่มีค่า 1 (ใช้งานจริง): 12 ช่อง
(12 / 49) × 100% = 24.49%
ช่องที่มีค่า 0 (สูญเปล่า / ไม่ได้ใช้งาน): 37 ช่อง
(37 / 49) × 100% = 75.51%
💡 สรุปคำสอนอาจารย์: เพราะกราฟส่วนใหญ่เป็นแบบ Sparse Graph พื้นที่กว่า 75% สิ้นเปลืองไปกับการเก็บ 0 จึงไม่นิยมใช้ Matrix และเปลี่ยนไปใช้ Adjacency List แทน

📦 Circular Queue Array (Indices 0..6)

ขนาดคิว N = 7 ช่อง: ดัชนี [0]=1, [1]=2, [2]=5, [3]=4, [4]=7, [5]=3, [6]=6

05 — กฎเหล็กข้อสอบ & ดาวน์โหลดเอกสาร

ข้อควรระวังเพื่อป้องกันการได้ 0 คะแนน

กฎการตรวจข้อสอบอย่างเข้มงวดของอาจารย์ประดิษฐ์

⚠️ กฎเหล็กจุดตัด 0 คะแนน: ห้ามเขียนลูกศร "->" เด็ดขาด!

ทั้งในโจทย์การเขียน Path (Undirected Graph, Directed Graph) และ Topological Sort อาจารย์เน้นย้ำหลายรอบว่า "ต้องคั่นด้วยเครื่องหมายจุลภาค (Comma) เท่านั้น ห้ามใส่ลูกศร -> เด็ดขาด หากเขียนลูกศรจะถูกหักเหลือ 0 คะแนนทันที"

❌ 1 -> 2 -> 5 -> 4 -> 3 -> 7 -> 6 (0 คะแนน)
✅ 1, 2, 5, 4, 3, 7, 6 (ได้คะแนนเต็ม)
