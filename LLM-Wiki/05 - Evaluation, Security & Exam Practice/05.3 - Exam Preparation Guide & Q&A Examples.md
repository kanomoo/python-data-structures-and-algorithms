## 🧮 หมวดที่ 1: การคำนวณมิติเมทริกซ์และหน่วยความจำ VRAM (Matrix & VRAM Calculations)

### ❓ ข้อที่ 1: การคำนวณมิติเมทริกซ์ $Q, K, V$ และ Attention Matrix
**โจทย์**: สมมติประมวลผลประโยคที่มีความยาว $N = 512$ tokens โดยใช้โมเดลที่มีขนาด $d_{\text{model}} = 4096$ และแบ่งเป็น Multi-Head Attention จำนวน $h = 32$ heads
1. จงหามิติของ $d_k$ ต่อ 1 Head
2. จงหามิติของเมทริกซ์ $Q, K, V$ ใน 1 Head
3. จงหามิติของ Attention Weights Matrix ก่อนคูณกับ $V$
4. จงหามิติตัวแปรผลลัพธ์รวมหลังทำการ Concatenate ทุก Heads และคูณด้วย $W_O$

**✏️ เฉลยละเอียด**:
1. $d_k = d_{\text{model}} / h = 4096 / 32 = \mathbf{128}$
2. $Q, K, V \in \mathbb{R}^{N \times d_k} \implies \mathbf{(512, 128)}$
3. $\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)$ เกิดจาก $Q(512, 128) \times K^T(128, 512) \implies \mathbf{(512, 512)}$
4. ผลลัพธ์รวมทุก Heads (32 heads $\times 128 = 4096$) คูณด้วย $W_O(4096, 4096) \implies \mathbf{(512, 4096)}$

---

### ❓ ข้อที่ 2: การคำนวณ VRAM สำหรับโหลด Weights ของโมเดล
**โจทย์**: โมเดล Llama-3 ขนาด 70 Billion parameters ต้องใช้หน่วยความจำ VRAM อย่างน้อยเท่าใดในการโหลดตัวน้ำหนักโมเดล (Model Weights) สำหรับการ Inference ในฟอร์แมต:
1. FP16 (16-bit Float)
2. INT8 (8-bit Quantized)
3. INT4 (4-bit Quantized)

**✏️ เฉลยละเอียด**:
สูตร: $\text{VRAM (GB)} = P \times \text{Bytes per parameter}$
1. **FP16**: 16 bits = 2 Bytes $\implies 70 \times 10^9 \times 2 = 140 \times 10^9 \text{ Bytes} = \mathbf{140 \text{ GB}}$
2. **INT8**: 8 bits = 1 Byte $\implies 70 \times 10^9 \times 1 = \mathbf{70 \text{ GB}}$
3. **INT4**: 4 bits = 0.5 Bytes $\implies 70 \times 10^9 \times 0.5 = \mathbf{35 \text{ GB}}$

---

### ❓ ข้อที่ 3: การคำนวณหน่วยความจำ KV Cache สำหรับ Context ยาว
**โจทย์**: โมเดลแบบ GQA มี $l = 40$ layers, $h_{kv} = 8$ heads, $d_k = 128$, ใช้ชนิดข้อมูล FP16 ($S = 2$ bytes) ถ้ามีผู้ใช้รัน Batch Size $b = 4$ พร้อมกันที่ Sequence Length $t = 8,192$ tokens จงคำนวณขนาด KV Cache ในหน่วยความจำ VRAM

**✏️ เฉลยละเอียด**:
สูตร: $\text{KV Cache Memory} = 2 \times b \times t \times l \times h_{kv} \times d_k \times S$
$$\text{Memory} = 2 \times 4 \times 8192 \times 40 \times 8 \times 128 \times 2$$
$$\text{Memory} = 2 \times 4 \times 8192 \times 40 \times 8 \times 128 \times 2 = 5,368,709,120 \text{ Bytes}$$
$$\text{Memory in GB} = \frac{5,368,709,120}{1024^3} = \mathbf{5.0 \text{ GB}}$$

---

### ❓ ข้อที่ 4: การคำนวณพารามิเตอร์ที่ลดลงจาก LoRA
**โจทย์**: เลเยอร์ Linear Projection มีขนาด $d_{\text{in}} = 8192, d_{\text{out}} = 8192$ หากประยุกต์ใช้ LoRA ด้วย Rank $r = 16$ จงคำนวณ:
1. จำนวนพารามิเตอร์ของน้ำหนักเดิม $W_0$
2. จำนวนพารามิเตอร์ของเมทริกซ์ LoRA ($A + B$)
3. อัตราส่วนพารามิเตอร์ที่ลดลง (%)

**✏️ เฉลยละเอียด**:
1. **$W_0$**: $8192 \times 8192 = \mathbf{67,108,864}$ พารามิเตอร์
2. **LoRA ($A$ และ $B$)**:
   - Matrix $A \in \mathbb{R}^{16 \times 8192} \implies 131,072$
   - Matrix $B \in \mathbb{R}^{8192 \times 16} \implies 131,072$
   - รวม = $131,072 + 131,072 = \mathbf{262,144}$ พารามิเตอร์
3. **เปอร์เซ็นต์การลดพารามิเตอร์**:
   $$\% = \left( 1 - \frac{262,144}{67,108,864} \right) \times 100\% = 1 - 0.003906 = \mathbf{99.61\%}$$

### ❓ ข้อที่ 5: การคำนวณ Chinchilla Optimal Dataset Size
**โจทย์**: บริษัทต้องการเทรนโมเดลขนาด $N = 14 \text{ Billion parameters}$ ให้ได้ประสิทธิภาพสูงสุดตามหลัก Chinchilla Scaling Law ต้องเตรียมชุดข้อมูลสำหรับ Pre-training อย่างน้อยกี่ Tokens?

**✏️ เฉลยละเอียด**:
ตามกฎ Chinchilla Optimal Ratio: อัตราส่วน $D / N \approx 20$
$$D = 20 \times N = 20 \times 14 \times 10^9 = \mathbf{280 \text{ Billion Tokens}}$$

## 🎲 หมวดที่ 2: อัลกอริทึมและการสุ่มคำตอบ (Decoding & Sampling)

### ❓ ข้อที่ 6: Step-by-Step คำนวณ Top-p (Nucleus Sampling)
**โจทย์**: โมเดลคำนวณค่าความน่าจะเป็นของโทเคน 6 ตัวแรกได้ดังนี้:
`[Token A: 0.35, Token B: 0.25, Token C: 0.20, Token D: 0.10, Token E: 0.06, Token F: 0.04]`
หากกำหนด **Top-p = 0.75** จงแสดงขั้นตอนการเลือกกลุ่มโทเคนที่จะถูกคัดไว้สำหรับการสุ่ม และแสดงค่าความน่าจะเป็นใหม่หลังทำการ Re-normalization

**✏️ เฉลยละเอียด**:
1. **เรียงลำดับความน่าจะเป็นจากมากไปน้อย**:
   - A (0.35), B (0.25), C (0.20), D (0.10), E (0.06), F (0.04)
2. **คำนวณความน่าจะเป็นสะสม (Cumulative Probability)**:
   - A: $0.35 \le 0.75 \to \text{เอา}$
   - A + B: $0.35 + 0.25 = 0.60 \le 0.75 \to \text{เอา}$
   - A + B + C: $0.60 + 0.20 = 0.80 > 0.75 \to$ **เอา C เป็นตัวสุดท้าย! (เพราะรวมแล้วครอบคลุมถึงจุด 0.75)**
3. **กลุ่มที่คัดไว้**: `{Token A, Token B, Token C}` (ผลรวมเดิม $= 0.80$)
4. **Re-normalization (ปรับผลรวมให้เท่ากับ 1.0)**:
   - $P'(A) = 0.35 / 0.80 = \mathbf{0.4375}$
   - $P'(B) = 0.25 / 0.80 = \mathbf{0.3125}$
   - $P'(C) = 0.20 / 0.80 = \mathbf{0.2500}$

### ❓ ข้อที่ 7: ผลกระทบของ Temperature ($T$) ต่อ Softmax Probability
**โจทย์**: อธิบายความแตกต่างของผลลัพธ์ Softmax เมื่อตั้งค่า $T = 0.1$ เทียบกับ $T = 2.0$

**✏️ เฉลยละเอียด**:
- **สูตร**: $P(y_i) = \frac{\exp(z_i / T)}{\sum \exp(z_j / T)}$
- **เมื่อ $T = 0.1$ (ต่ำมาก)**: ค่า Logits $z_i / 0.1 = 10 \cdot z_i$ จะถูกขยายความแตกต่างอย่างรุนแรง ค่าสูงสุดจะโดดขึ้นไปใกล้ 1.0 ส่วนค่าอื่นดร็อปเป็น 0.0 พฤติกรรมโมเดลกลายเป็น **Greedy Deterministic**
- **เมื่อ $T = 2.0$ (สูงมาก)**: ค่า Logits ถูกหารครึ่ง ทำให้ความแตกต่างลดลง ค่าความน่าจะเป็นถูกเกลี่ยจนแบนราบ (Uniform Distribution) คำตอบจะหลากหลาย สุ่มสูง และเสี่ยงเกิด Hallucination

## 🏛️ หมวดที่ 3: สถาปัตยกรรมและบทพิสูจน์ทางคณิตศาสตร์ (Architecture Proofs)

### ❓ ข้อที่ 8: พิสูจน์ทำไม $q \cdot k$ ถึงมีความแปรปรวนเท่ากับ $d_k$
**โจทย์**: จงแสดงบทพิสูจน์ว่าหากองค์ประกอบของ เวกเตอร์ $q, k \in \mathbb{R}^{d_k}$ เป็นตัวแปรสุ่มที่เป็นอิสระต่อกัน มีค่าเฉลี่ยเป็น 0 และความแปรปรวนเป็น 1 แล้ว $\text{Var}(q \cdot k) = d_k$

**✏️ เฉลยละเอียด**:
ให้ $q = [q_1, q_2, \dots, q_{d_k}]$ และ $k = [k_1, k_2, \dots, k_{d_k}]$
ผลคูณสเกลาร์ $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$
เนื่องจาก $q_i, k_i$ เป็นอิสระต่อกัน:
$$\mathbb{E}[q_i k_i] = \mathbb{E}[q_i] \mathbb{E}[k_i] = 0 \times 0 = 0$$
$$\text{Var}(q_i k_i) = \mathbb{E}[q_i^2 k_i^2] - (\mathbb{E}[q_i k_i])^2 = \mathbb{E}[q_i^2] \mathbb{E}[k_i^2] - 0 = \text{Var}(q_i) \text{Var}(k_i) = 1 \times 1 = 1$$
เนื่องจากแต่ละมิติเป็นอิสระต่อกัน ความแปรปรวนของผลรวมเท่ากับผลรวมของความแปรปรวน:
$$\text{Var}(q \cdot k) = \text{Var}\left( \sum_{i=1}^{d_k} q_i k_i \right) = \sum_{i=1}^{d_k} \text{Var}(q_i k_i) = \sum_{i=1}^{d_k} 1 = \mathbf{d_k}$$
*(จึงเป็นสาเหตุที่ต้องหารด้วย $\sqrt{d_k}$ เพื่อปรับให้ Variance กลับมาเป็น 1)*

### ❓ ข้อที่ 10: ความแตกต่างระหว่าง Pre-LN และ Post-LN
**โจทย์**: เหตุใด LLM ยุคใหม่ (เช่น GPT-3, Llama) จึงเปลี่ยนมาใช้ Pre-LayerNorm แทน Post-LayerNorm ดั้งเดิมของ Transformer 2017?

**✏️ เฉลยละเอียด**:
- **Post-LN**: วาง LayerNorm ไว้หลังการบวก Residual ($x_{l+1} = \text{LN}(x_l + F(x_l))$) ทำให้ Gradient ที่ไหลกลับในสเต็ป Backprop ต้องผ่าน LN ทุกครั้ง ส่งผลให้ Gradient สเกลเล็กลงเรื่อยๆ เมื่อโมเดลลึกขึ้น เกิดปัญหา **Gradient Vanishing** ต้องใช้อัตราการเรียนรู้แบบ Warmup ที่ละเอียดอ่อนมาก
- **Pre-LN**: วาง LayerNorm ไว้ก่อนเข้า Sub-layer ($x_{l+1} = x_l + F(\text{LN}(x_l))$) ทำให้เกิด **Identity Shortcut Path ($x_l$)** ที่สะอาด ช่วยให้ Gradient สามารถไหลย้อนกลับจาก Layer บนสุดถึง Layer แรกได้โดยตรงโดยไม่ถูกสเกลลง ทำให้เทรนโมเดลความลึกสูงๆ ได้เสถียรมาก

### ❓ ข้อที่ 11: เปรียบเทียบ DPO และ RLHF (PPO)
**โจทย์**: อธิบายข้อได้เปรียบหลัก 3 ประการของ Direct Preference Optimization (DPO) ที่เหนือกว่า RLHF แบบ PPO ดั้งเดิม

**✏️ เฉลยละเอียด**:
1. **ไม่ต้องมี Reward Model แยก**: DPO ใช้สูตร Implicit Reward คำนวณตรงจาก Policy Model และ Reference Model
2. **ประหยัด Memory VRAM**: ไม่ต้องโหลดโมเดล Critic และ Reward Model เข้า GPU พร้อมกัน
3. **เสถียรภาพในการเทรนสูง**: DPO เป็นการปรับสเกล Loss แบบ Supervised Closed-form ไม่เกิดปัญหาการหลุด Convergence หรือ Reward Hacking เหมือนอัลกอริทึม Reinforcement Learning (PPO)

### ❓ ข้อที่ 14: การคำนวณ RRF (Reciprocal Rank Fusion) ใน Hybrid Search
**โจทย์**: ระบบ RAG ทำงานแบบ Hybrid Search ได้ผลการจัดอันดับเอกสาร $Doc_A$ ดังนี้:
- Dense Vector Search: จัดอยู่อันดับที่ $r_1 = 2$
- Sparse BM25 Search: จัดอยู่อันดับที่ $r_2 = 5$
หากกำหนดค่า constant $k = 60$ จงคำนวณคะแนน RRF Score ของ $Doc_A$

**✏️ เฉลยละเอียด**:
$$\text{RRF Score} = \sum_{m \in M} \frac{1}{k + r_m(d)}$$
$$\text{RRF Score}(Doc_A) = \frac{1}{60 + 2} + \frac{1}{60 + 5} = \frac{1}{62} + \frac{1}{65} \approx 0.016129 + 0.015384 = \mathbf{0.031513}$$

### ❓ ข้อที่ 15: คำนวณ Active vs Total Parameters ใน MoE
**โจทย์**: โมเดล Sparse MoE มี 8 Experts แต่ละ Expert มีขนาด 6 Billion parameters และมีส่วนแชร์ดั้งเดิม (Self-Attention, Embeddings) ขนาด 4 Billion parameters หากโมเดลตั้งค่า Router ให้เลือก Top-2 Experts จงคำนวณ Total Parameters และ Active Parameters ต่อ 1 Token

**✏️ เฉลยละเอียด**:
1. **Total Parameters**:
   $$\text{Total} = \text{Shared} + (\text{Num Experts} \times \text{Expert Size}) = 4\text{B} + (8 \times 6\text{B}) = \mathbf{52 \text{ Billion parameters}}$$
2. **Active Parameters per Token**:
   $$\text{Active} = \text{Shared} + (\text{Top-k} \times \text{Expert Size}) = 4\text{B} + (2 \times 6\text{B}) = \mathbf{16 \text{ Billion parameters}}$$

- **ข้อ 21: Speculative Decoding ปรับปรุงความเร็วโดยที่คุณภาพโมเดลเปลี่ยนไปหรือไม่?**
  - *ตอบ*: ไม่เปลี่ยนเลย 100% (Mathematical Equivalence) เพราะใช้ Rejection Sampling ในการตรวจรับรอง
- **ข้อ 22: ปรากฏการณ์ Hallucination ใน LLM คืออะไร และ RAG ช่วยแก้ได้อย่างไร?**
  - *ตอบ*: การสร้างข้อมูลเท็จที่น่าเชื่อถือ RAG ช่วยแก้โดยการบังคับอ้างอิงข้อมูลจริงจากภายนอก (Grounding)
- **ข้อ 23: Indirect Prompt Injection ต่างจาก Direct Prompt Injection อย่างไร?**
  - *ตอบ*: Direct เกิดจากผู้ใช้ป้อนคำสั่งโดยตรง, Indirect เกิดจากคำสั่งอันตรายแฝงมากับเอกสารภายนอกที่ RAG หรือ Agent ไปดึงมา
- **ข้อ 24: GRPO ใน DeepSeek ตัดโมเดลส่วนใดใน PPO ออก?**
  - *ตอบ*: ตัดโมเดล Critic Network ออก โดยใช้ค่าเฉลี่ยผลตอบแทนของกลุ่มคำตอบ (Group Mean Baseline) แทน
- **ข้อ 25: ใน BPE Tokenizer หากพบคำที่ไม่เคยเห็นในคลังข้อมูล จะเกิดอะไรขึ้น?**
  - *ตอบ*: คำนั้นจะถูกซอยย่อยลงไปเรื่อยๆ จนถึงระดับตัวอักษรเดี่ยว (Characters) จึงไม่เกิดปัญหา Out-of-Vocabulary (OOV)
