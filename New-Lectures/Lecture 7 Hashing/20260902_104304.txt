อาจารย์:
"เพิ่มขึ้นตามไปด้วยนะครับ เมื่อสมาชิกใน Hash Table มากขึ้น นะครับ ต่อครับ
Running time ก็คือเวลาที่ใช้ในการทำงาน เวลาที่ใช้ในการทำงานของโอเปอเรชันต่างๆ นั้น ก็จะ start taking too long ก็จะเริ่มใช้เวลามากขึ้น นะครับ การ insert การค้นหา การลบ เป็นต้น นะครับ
and insertion might fail และบางครั้งการใส่ข้อมูลนั้นอาจจะ ใส่ไม่ได้
fail ก็คือใส่ไม่ได้นะครับ เช่น 23 ที่ฝากมาเป็นต้น ใช่ไหมครับ คุณจะแก้การชนกันไปอีก 100 รอบ มันก็ใส่ไม่ได้ นะครับ

สาเหตุที่เป็นเช่นนั้นก็เพราะว่า มันใกล้จะเต็มนั่นเอง
Solution วิธีแก้: วิธีแก้นะครับ ในกรณีที่ Hash Table มันใกล้จะเต็ม ใกล้เต็มเพราะเราใส่ข้อมูลเข้าไปมาก นะครับ
วิธีแก้นะครับ เขาเรียกว่า Rehashing
Rehashing ก็คือ เราจะทำการสร้าง Hash Table ขึ้นมาใหม่ ที่มีขนาดใหญ่กว่าเดิมเป็น 2 เท่า
แล้วเราก็จะโยกย้ายข้อมูลจาก Hash Table เดิม ไปใส่ใน Hash Table ใหม่
ก็คือขนาด ขยาย ขยาย Hash Table ให้มันใหญ่ขึ้นนั่นเอง นะครับ เพื่อให้มันมีช่องว่างมากขึ้น ใช่ไหมครับ ต่อครับ

เราจะสร้าง Hash Table ขึ้นมาใหม่ให้มีขนาดใหญ่กว่าเดิมเป็น 2 เท่า นะครับ อันนี้เป็นวิธีทำของเขา
เราจะทำการ rehash เขาเรียกว่า resize นะครับ
เมื่อสมาชิกใน Table มากกว่า 0.5, 0.5 ก็คือมากกว่า 50% ขึ้นไป เราก็เริ่มคิดที่จะ rehash แล้ว นะครับ
หรือเมื่อเราใส่ข้อมูลแล้วเราพบว่า มันใส่ไม่ได้หลายๆ เลข ข้อมูลหลายๆ ตัว พยายามจะใส่แล้วมันใส่ไม่ได้ เราก็จะ rehashing นะครับ

อะ เรามาดูตัวอย่าง Rehashing ครับ อยู่ในหน้า 19 สไลด์หน้า 19 ครับ
Rehashing hash example นะครับ อ่านพร้อมๆ กันนะครับ
สมมุติ สมมุติมี Hash Table อยู่ 0 ถึง 6, 0 ถึง 6 ก็แปลว่ามี 7 ช่อง นะครับ
อย่าลืมนะ Hash Table ตัวชี้ตำแหน่ง ตำแหน่งที่ 0 อยู่ข้างบนนะครับนักศึกษา แล้วก็ไล่ลงมา 0, 1, 2, 3, 4, 5, 6 นะครับ
ทำไมผมต้องบอกแบบนี้ เพราะเคยมีรุ่นพี่คุณนะครับ ให้ 0 อยู่ข้างล่าง พอ 0 อยู่ข้างล่างแล้วคำนวณผิดนะครับนักศึกษา อันนี้ให้ 0 อยู่ข้างบนนะ
0 ถึง 6 ก็แปลว่ามี 7 ช่อง

อะ เริ่มนะครับ เขาบอกว่า สมมุติให้เราใส่ข้อมูลเข้าไปใน Hash Table 13, 15, 24 แล้วก็ 6 ใส่เข้าไปใน Hash Table นะครับ
ใช้วิธีการ Open Addressing ก็คือ ข้อมูลใส่เข้าไปจริงๆ
Hash Table มีขนาดเท่ากับ 7 ดังนั้น ฟังก์ชันแฮชมาตรฐาน ก็คือ x mod 7 ทันไหมครับ 7 คือ Table Size
Linear Probing is used ใช้วิธีการ Linear Probing ในการแก้การชนกัน ถ้ามีการชนกันก็แก้ด้วยวิธี Linear อันนี้โจทย์สมมุตินะครับ
ตอนสอบปลายภาคก็จะทรงนี้นะครับนักศึกษา ก็คือ มี Hash Table เปล่าๆ มาให้ มีข้อมูล ส่วนใหญ่จะให้มาเป็นเลข มีวิธีแก้การชนกัน ให้ใช้วิธีใด ในข้อสอบโจทย์ก็จะคล้ายๆ อย่างนี้

เวลาใส่ เราก็ใส่ทีละตัวจากซ้ายไปขวา
เริ่มแรก 13, 13 ลงช่องไหน 13 mod 7 ได้ 6 ใส่ 13 ลงช่องที่ 6
ตัวถัดไป 15, 15 mod 7 ได้เศษ 1 ใส่ 15 ลงช่องที่ 1
ตัวถัดไป 24, 24 mod 7 ได้เศษ 3 (7*3=21, 24-21=3) ใส่ 24 ลงช่องที่ 3
ตัวถัดไป 6, 6 mod 7 ได้เศษ 6 แต่ช่อง 6 มี 13 อยู่ ชนกัน! แก้ด้วย Linear Probing ดูช่องถัดไป ช่องถัดไปเกินตาราง เกิด Wrap Around วนกลับมาช่องที่ 0 ช่อง 0 ว่าง ใส่ 6 ลงช่องที่ 0

พอใส่ลงไปเสร็จ เราก็ต้องคำนวณครับนักศึกษา
วิธีคำนวณ ช่วยจดลงไปหน่อยนะ วิธีคำนวณเขาเรียกว่า เทียบบัญญัติไตรยางศ์ หรือร้อยละ
จำนวนช่องใน Hash Table โจทย์บอกว่ามี 7 ช่อง ตอนนี้ใส่ไปแล้วกี่ช่อง? เอานิ้วนับ 1, 2, 3, 4 มี 4 ตัว
ตั้งบัญญัติไตรยางศ์ครับ:
7 ช่อง ใช้ไป 4
ถ้า 100 ช่อง คิดเป็นกี่เปอร์เซ็นต์?
เอา 100 ไปคูณ 4 แล้วเอา 7 ลงมาหาร:
400 / 7 = 57.14% จดลงไปครับ

โจทย์หน้าถัดไปบอกว่า ถ้าเราใส่ 23 เพิ่มเข้าไปอีกตัวหนึ่ง
ถ้าใส่ 23 เพิ่มเข้าไปอีกตัวหนึ่ง ตารางจะกลายเป็นใช้ไป 5 ช่อง จาก 7 ช่อง
The table is over 70% full โจทย์กำหนดเงื่อนไขว่า ถ้าข้อมูลเกินกว่า 70% ให้ทำ Rehashing!
เราคิดเปอร์เซ็นต์: 5 ช่องจาก 7 ช่อง -> (5 * 100) / 7 = 71.42%!
71.42% มันเกิน 70% หรือยัง? เกินแล้ว! จึงต้องทำ Rehashing!

Rehashing ทำยังไง?
สร้าง Hash Table ขึ้นมาใหม่ให้ใหญ่กว่าเดิมเป็น 2 เท่า
ของเดิมมี 7 ช่อง 2 เท่าคือ 2 * 7 = 14 แต่เราไม่เลือก 14!
ทำไมไม่เลือก 14? เพราะ 14 ไม่ใช่เลขจำนวนเฉพาะ!
กฎการเลือก Table Size ใหม่:
Choose the smallest prime number greater than or equal to double of the table size of the old hash table!
เลือก Table Size เป็นเลขจำนวนเฉพาะที่น้อยที่สุด แต่มากกว่าหรือเท่ากับ 2 เท่าของ Hash Table เดิม!
2 เท่าของ 7 คือ 14 นับต่อไปหาจำนวนเฉพาะ: 14 ไม่ใช่, 15 ไม่ใช่, 16 ไม่ใช่, 17 ใช่!
ดังนั้น Hash Table ใหม่จึงมี 17 ช่อง (Index 0 ถึง 16)!

ฟังก์ชันแฮชใหม่ก็ต้องแก้เป็น: hash(x) = x mod 17!
แล้วเวลาอ่านข้อมูลจาก Hash Table เดิมไปใส่ใน Hash Table ใหม่
กฎสำคัญมาก ฟังดีๆ:
ต้องอ่านตามลำดับที่ปรากฏใน Hash Table เดิมจากบนลงล่าง คืออ่านช่อง 0, 1, 2, 3... ลงมา:
ได้แก่ 6, 15, 24, 13!
ไม่ใช่ไปอ่านจากโจทย์ตั้งต้น 13, 15, 24, 6 นะครับ!
รุ่นพี่คุณทำผิดเยอะมาก ไปอ่านจากโจทย์ตั้งต้น ผิดทันที ได้ 0!
ต้องอ่านจาก Hash Table เดิมที่คำนวณตำแหน่งและแก้การชนมาแล้ว คือ 6, 15, 24, 13 แล้วนำมา mod 17 ใส่ลงตารางใหม่ทีละตัวครับ!"
